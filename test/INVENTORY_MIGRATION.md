# 老项目迁移

1. 在 old `otherproject` 应用的“我的 → 导出”分别导出分类和物品。
2. 导出通常在 `Download/csv`：`导出分类_时间.csv`、`导出物品_时间.csv`，以及与物品 CSV 同名的图片文件夹。若使用应用专属目录，请用可访问该目录的文件管理方式取出，CSV 不要用 Excel 另存为其他编码。
3. 在新应用“我的 → 导入万物数据”，先选择分类 CSV 并合并导入，再选择物品 CSV，选择旁边的同名图片文件夹，再合并导入。界面先预览数量，实际导入前确认。
4. 新应用“导出万物数据”保存一个含物品、分类和图片的 JSON，在同一导入入口恢复。

合并规则：现有物品和菜谱保留，旧 ID 不占用新 ID；类别按名称合并，说明和排序使用导入值，旧分类 ID 单独保存映射。物品按除图片外的字段逐条匹配已有记录（保留源数据内的真实重复数量），已有图片按字节比对，可补缺图。校验失败不写入数据，事务失败清理本次新建图片。

范围：万物分类、物品与图片。旧分类的创建时间、首页展示不映射到新功能；菜谱和提醒天数不包含在此 JSON。日期要求真实的 2000–2100 年日期。Android 系统文件选择器，无新增存储权限和依赖。最大文件 100 MB、单图片 20 MB、图片目录总计 100 MB；备份照片总量 65 MB，预留 Base64 空间。

图片兼容：旧 exporter 对同 basename 自动加序号但 CSV 保留原路径，且跳过不存在的源文件，极端情况下无法还原对应关系。本次为 otherproject exporter 增加 `image_manifest.json` 原路径映射，新应用自动读取。已有无 manifest 的旧导出仍可迁移唯一 basename 图；存在不同来源但同名图时跳过并报告，避免串图。需要完整迁移这些图时，用更新后的旧应用重新导出。

验证：Dart 静态分析通过。新增 `inventory_transfer_test.dart` 覆盖 OpenCSV 引号、逗号、多行备注、BOM、各版本分类列、日期非法、格式错误及图片 JSON 往返/缺失。遵循用户先前选择，本轮未执行 Flutter 测试和 Android 构建；Kotlin SAF、真机文件选择和 SQLite 导入尚需运行验收。

后续检查：`flutter test test/inventory_transfer_test.dart`，`flutter build apk --debug`。真机验收包括先分类后物品、照片预览、重复导入、部分照片补导、非法CSV不改变数据、新JSON导出后导入、取消文件选择、换CSV不复用旧图片文件夹、同名图片manifest。
